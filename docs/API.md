# Ishaara API

This is the reference for every HTTP endpoint the backend exposes, with what each is for.
The live, machine-readable version is generated by the running service at `/docs`
(Swagger UI) and `/openapi.json`. A ready-to-use Postman collection is in
[`docs/postman/`](postman/README.md).

> **Status after M5:** a submitted video is analysed, narrated and voiced, and the result can be
> read back as cues (JSON), a WebVTT description track and accessible notes. The only planned
> endpoint left is `POST /v1/videos/{video_key}/questions` (M6).

## What the service does

A student pastes a YouTube lecture link. The backend finds the moments where something
appears on the board or screen that the teacher did not explain aloud, writes a short
spoken description of each, and voices it. The frontend then plays the lecture, pauses at
each moment, plays the description, and resumes. Videos are public YouTube videos only;
the backend never downloads video, Gemini reads it from YouTube.

## Basics

| | |
| --- | --- |
| Base URL | Local: `http://localhost:8000`. Deployed: the Cloud Run service URL. |
| Content type | JSON (`application/json`) |
| Authentication | `Authorization: Bearer <Firebase ID token>` on every `/v1` route |
| CORS | Only origins listed in `ALLOWED_ORIGINS` |
| Errors | RFC 9457 problem details, `application/problem+json` (see below) |

**Getting a token.** The frontend signs the user in with Firebase Auth and sends
`await currentUser.getIdToken()`. Tokens expire after an hour; ask Firebase for a fresh one
on each session. For local development only, setting `AUTH_BYPASS_UID` in `.env` makes
every request act as that user with no token at all. The setting is refused when
`ENVIRONMENT=production`.

### Errors

Every failure, including validation errors, unknown routes and unexpected crashes, has the
same shape:

```json
{
  "type": "https://ishaara.app/errors/video_too_long",
  "title": "Video is too long",
  "status": 422,
  "detail": "This video is 74 minutes; the limit is 45 minutes.",
  "code": "video_too_long"
}
```

Branch on `code`, not on `detail`; `detail` is for humans.

| `code` | HTTP | When |
| --- | --- | --- |
| `invalid_token` | 401 | Missing, malformed, expired or rejected token |
| `invalid_youtube_url` | 400 | The link is not a YouTube video |
| `invalid_request` | 422 | Body or parameter failed validation; `detail` names the field |
| `video_not_public` | 422 | Video is private or unlisted |
| `video_not_embeddable` | 422 | The owner disabled embedding |
| `video_is_live` | 422 | Live or upcoming broadcast |
| `video_too_long` | 422 | Longer than `MAX_VIDEO_MINUTES` (45) |
| `video_not_found` | 404 | No YouTube video with that id, or no stored video with that `video_key` |
| `video_not_ready` | 409 | Cues, WebVTT or notes requested before the video is `ready`, or it `failed` |
| `daily_limit_reached` | 429 | The user used up `DAILY_VIDEO_LIMIT` (10) new videos, or `DAILY_QUESTION_LIMIT` (50) questions, today (UTC) |
| `youtube_unavailable` | 502 | The YouTube Data API kept failing |
| `gemini_error` | 502 | A Gemini call failed. Appears as a video's `error_code`. |
| `gemini_invalid_response` | 502 | Gemini returned unusable output. Appears as a video's `error_code`. |
| `storage_error` | 502 | A file could not be stored |
| `internal_error` | 500 | Unexpected server error (details are only in the server logs) |
| `not_found` / `method_not_allowed` | 404 / 405 | Unknown route or wrong method |

### `POST /v1/videos`

**Use case:** the student submits a lecture link. This starts processing, or returns the
finished result straight away if someone already processed the same video in the same
language.

**Request body**

| Field | Type | Notes |
| --- | --- | --- |
| `youtube_url` | string, 1 to 300 chars | `youtube.com/watch?v=`, `m.youtube.com/watch?v=`, `youtu.be/`, `/shorts/`, `/embed/`, `/live/`, or a bare 11-character id. Extra parameters such as `&t=` and `&list=` are ignored. |
| `narration_language` | `"en"` or `"hi"` | Language of the spoken descriptions |

```bash
curl -X POST http://localhost:8000/v1/videos \
  -H "Authorization: Bearer $FIREBASE_ID_TOKEN" -H "Content-Type: application/json" \
  -d '{"youtube_url": "https://youtu.be/v8kBd64_WAc", "narration_language": "en"}'
```

**Responses** (body is a [status object](#status-object))

| Status | Meaning |
| --- | --- |
| `202 Accepted` | Queued, already processing, or restarted. Poll `GET /v1/videos/{video_key}`. |
| `200 OK` | Already `ready`; nothing to wait for. |
| `400` `422` `404` `429` `502` | See the error table above |

```json
{
  "video_key": "v8kBd64_WAc_en_v2",
  "status": "queued",
  "stage": null,
  "progress_percent": 0,
  "title": "Circular Tracks for CAT Exam | CAT Arithmetic Concepts & Question Types",
  "duration_seconds": 527,
  "error_code": null,
  "error_message": null
}
```

**Behaviour worth knowing**

- `video_key` is `{youtube_id}_{language}_v{pipeline_version}`. Everyone who submits the
  same video in the same language shares one job and one result, so a popular lecture is
  analysed once.
- A `ready` result is returned instantly and does **not** use the daily limit.
- A job that is already running is joined, not duplicated, and does not use the limit.
- A `failed` job, or one whose worker stopped sending heartbeats (about 90 seconds), is
  restarted. A restart uses one unit of the daily limit.
- A new video is checked with YouTube first (public, embeddable, not live, not too long).
  An invalid video returns its 422 without using the limit and without storing anything.
- The submission is added to the caller's history either way.

### `GET /v1/videos/{video_key}`

**Use case:** the polling endpoint. The frontend calls it every 3 seconds after a `202`,
to draw a progress bar and to learn when the result is ready or has failed.

```bash
curl http://localhost:8000/v1/videos/v8kBd64_WAc_en_v2 -H "Authorization: Bearer $FIREBASE_ID_TOKEN"
```

Returns a [status object](#status-object), or `404 video_not_found`. Any signed-in user can
read any `video_key`; the videos are public YouTube videos.

#### Status object

| Field | Type | Meaning |
| --- | --- | --- |
| `video_key` | string | Identifier used in every other video route |
| `status` | `queued`, `processing`, `ready`, `failed` | Lifecycle state |
| `stage` | string or null | Set while `processing` (see below) |
| `progress_percent` | 0 to 100 | Rough progress; never goes backwards |
| `title` | string | YouTube title |
| `duration_seconds` | integer | Video length |
| `error_code` | string or null | Set when `failed` (see the error table) |
| `error_message` | string or null | Human-readable reason |

**Lifecycle:** `queued` → `processing` → `ready` or `failed`.

| `stage` | `progress_percent` | What is happening |
| --- | --- | --- |
| `resolving` | 1 | Re-checking the video with YouTube |
| `analyzing` | 5 to 70 | Gemini watches the video in 10-minute windows and judges what the speech leaves unexplained |
| `writing` | 75 to 80 | Writing a short spoken line for each moment |
| `voicing` | 80 to 98 | Turning each line into audio |
| `saving` | 99 | Storing the transcript |

Timing depends on the lecture; a 9-minute lecture took about two minutes to analyse before
narration and voice were added. Show the stage to the student rather than a fake ETA.

### `GET /v1/videos/{video_key}/cues`

**Use case:** the player. After a video is `ready`, the frontend loads the cues once and
drives the YouTube IFrame player from them (pause at `start_seconds`, play `audio_url`,
resume). See [the cue object](#the-cue-object).

```bash
curl http://localhost:8000/v1/videos/v8kBd64_WAc_en_v2/cues -H "Authorization: Bearer $FIREBASE_ID_TOKEN"
```
```json
{
  "cues": [
    {
      "cue_id": "cue-0001",
      "start_seconds": 23.0,
      "spoken_phrase": "A and B are running either in the same direction",
      "referent_kind": "diagram",
      "board_description": "A starting tick mark at the bottom of the circle, labelled A and B, with arrows pointing counterclockwise.",
      "gap_summary": "A starting mark is drawn at the bottom of the circle labelled A and B, both with arrows pointing counterclockwise.",
      "narration_text": "On the board: A starting point is drawn at the bottom of the circular track with labels A and B, both with arrows pointing counterclockwise.",
      "audio_url": "https://<project>.supabase.co/storage/v1/object/public/narrations/audio/v8kBd64_WAc_en_v2/cue-0001.wav",
      "audio_duration_seconds": 10.48,
      "confidence": 0.9
    }
  ]
}
```

| Status | Meaning |
| --- | --- |
| `200` | Cues in time order. The list is empty if the teacher explained everything on screen. |
| `404 video_not_found` | No video with that key |
| `409 video_not_ready` | Still queued or processing, or it failed; `detail` says which and why |

### `GET /v1/videos/{video_key}/cues.vtt`

**Use case:** a standard WebVTT *descriptions* track (`Kind: descriptions`), for players and
assistive technology that support text-track descriptions, and as a plain-text fallback. One
cue per narration line, starting at the cue's time and lasting as long as the audio (or, for
a cue with no audio, an estimate from the word count), never running into the next cue.

```bash
curl http://localhost:8000/v1/videos/v8kBd64_WAc_en_v2/cues.vtt -H "Authorization: Bearer $FIREBASE_ID_TOKEN"
```
```text
WEBVTT
Kind: descriptions
Language: en

cue-0001
00:00:23.000 --> 00:00:33.480
On the board: A starting point is drawn at the bottom of the circular track with labels A and B.
```

Content type `text/vtt`. Same `404` and `409` behaviour as the cues endpoint.

**Browser note:** a `<track src="...">` element cannot send an `Authorization` header, so it
cannot load this URL directly. Fetch it with the token and attach the result as a blob URL:

```js
const vtt = await (await fetch(url, { headers: { Authorization: `Bearer ${token}` } })).text();
track.src = URL.createObjectURL(new Blob([vtt], { type: "text/vtt" }));
```

### `GET /v1/videos/{video_key}/notes`

**Use case:** accessible lecture notes a student can read with a screen reader or download:
the transcript in readable paragraphs, grouped into 5-minute sections, with each board
description inlined at the moment it appears as `**[Board, 02:42]** description`.

| Query | Default | Notes |
| --- | --- | --- |
| `format` | `markdown` | `markdown` (`text/markdown`) or `html` (`text/html`, a complete page). Anything else is `422 invalid_request`. |

```bash
curl "http://localhost:8000/v1/videos/v8kBd64_WAc_en_v2/notes?format=html" -H "Authorization: Bearer $FIREBASE_ID_TOKEN"
```
```markdown
# Circular Tracks for CAT Exam

Sayali Ma'am · 08:47 · narrated in English

## 00:00 – 05:00

Now what is a circular track? Instead of running in a straight line, people run in circles.

**[Board, 00:23]** A starting tick mark at the bottom of the circle with labels A and B and arrows.
```

- Section headings are `##` under a single `#` title, so heading levels are never skipped. The
  HTML page has `lang`, a `<title>` and a `<main>` landmark.
- Titles, transcript text and descriptions come from YouTube and Gemini, so they are escaped:
  they can never inject markup into the Markdown or HTML.
- If the transcript cannot be read, the notes still return with the board descriptions and
  say that the full transcript is not available. If there are no cues, they say that nothing
  needed describing.
- Same `404` and `409` behaviour as the cues endpoint.

### `POST /v1/videos/{video_key}/questions`

**Use case:** the student asks something the cues did not cover ("What was on the board at
12:40?", "Why did he divide by two?") and hears the answer spoken. It works on a finished
video only.

**Request body**

| Field | Type | Notes |
| --- | --- | --- |
| `question` | string, 1 to 500 characters | Trimmed. English or Hindi. |
| `at_seconds` | number or `null` | Where the student is in the video. Optional, at least 0 and not past the end of the video. |

```bash
curl -X POST http://localhost:8000/v1/videos/v8kBd64_WAc_en_v2/questions \
  -H "Authorization: Bearer $FIREBASE_ID_TOKEN" -H "Content-Type: application/json" \
  -d '{"question": "What is drawn on the board right now?", "at_seconds": 25}'
```
```json
{
  "answer_text": "A circle representing a track, with a tick mark at the bottom labelled A and B.",
  "answer_audio_url": "https://<project>.supabase.co/storage/v1/object/public/narrations/answers/v8kBd64_WAc_en_v2/3f9c1a....wav",
  "referenced_seconds": [23.0]
}
```

| Status | Meaning |
| --- | --- |
| `200` | The answer. `answer_audio_url` is `null` if the answer could not be voiced; the text is always there. |
| `404 video_not_found`, `409 video_not_ready` | No such video, or it has not finished processing |
| `422 invalid_request` | Blank or over-long question, negative `at_seconds`, or `at_seconds` past the end of the video |
| `429 daily_limit_reached` | The user already asked 50 questions today (UTC) |
| `502 gemini_error`, `gemini_invalid_response` | Gemini failed or returned nothing usable |

**How the answer is found**

1. With `at_seconds`, the transcript sentences and cue descriptions within 2 minutes either
   side are given to Gemini. Without it, all cue descriptions and the transcript are.
2. If that is not enough to say what was on the board **and** `at_seconds` was given, Gemini
   looks at the 30-second clip around that moment (15 seconds either side) and answers from
   the video. Without `at_seconds` a board question can only be answered from the text.
3. The answer is written in the language of the question (English or Hindi), and spoken in
   that language. The audio file has a random, unguessable public URL.

Each question counts against the daily limit before Gemini is called, so a question that then
fails on Gemini's side still uses one of the 50. Expect a few seconds for a text answer and
more when the video is looked at.

### `GET /media/{path}` (local development only)

**Use case:** plays narration audio when `STORAGE_BACKEND=local`, so the whole flow works
without any cloud account. Not authenticated. Cue `audio_url` values then look like
`http://localhost:8000/media/audio/<video_key>/cue-0001.wav`. In deployments the audio is in
a public Cloud Storage or Supabase Storage bucket and `/media` does not exist.

## The cue object

A finished video holds a list of cues, returned by `GET /v1/videos/{video_key}/cues`.

| Field | Meaning |
| --- | --- |
| `cue_id` | `cue-0001`, `cue-0002`, in time order |
| `start_seconds` | When the player should pause |
| `spoken_phrase` | What the teacher said around that moment (may be empty) |
| `referent_kind` | `equation`, `diagram`, `graph`, `code`, `table`, `text`, `physical_object` |
| `board_description` | Full description of what appeared on screen |
| `gap_summary` | What a listener would have missed |
| `narration_text` | The short spoken line (at most about 30 words) |
| `audio_url` | WAV file to play, or `null` if voicing failed for this cue |
| `audio_duration_seconds` | Length of that audio |
| `confidence` | 0 to 1 |

## How a frontend uses it

1. Sign the user in with Firebase and get an ID token.
2. `POST /v1/videos`. On `200`, skip to step 4.
3. Poll `GET /v1/videos/{video_key}` every 3 seconds. Show `stage` and `progress_percent`.
   Stop on `ready` or `failed`; on `failed`, show `error_message` and offer a retry (which
   is just another `POST`).
4. `GET /v1/videos/{video_key}/cues`, then play the YouTube video with the IFrame player. At each
   `cue.start_seconds`: `player.pauseVideo()`, play `cue.audio_url`, and on the audio's
   `ended` event `player.playVideo()`.
5. If a cue has no `audio_url`, show or read `narration_text` instead, for example through
   the screen reader, then resume. Offer the notes (`/notes?format=html`) as a reading alternative.

## Limits

| Limit | Value | Setting |
| --- | --- | --- |
| New videos per user per day (UTC) | 10 | `DAILY_VIDEO_LIMIT` |
| Questions per user per day (UTC) | 50 | `DAILY_QUESTION_LIMIT` |
| Question length | 500 characters | fixed |
| Longest video | 45 minutes | `MAX_VIDEO_MINUTES` |
| Gemini free tier | 8 hours of YouTube video per day across all users | Google's quota |
